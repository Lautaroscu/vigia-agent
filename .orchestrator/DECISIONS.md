# DECISIONS — log append-only del repo (lo escribe el orquestador)

Cada decisión de spec/arquitectura que tome el orquestador queda acá con su porqué. Así la próxima spec parte de lo ya decidido y no se re-discute.

Formato (agregar arriba, más reciente primero):

```md
## 2026-09-24 — <decisión>
- Porqué: ...
- Alternativas descartadas: ...
- TASKs afectadas: TASK-001, ...
```

El orquestador la actualiza con cada B (consecuencias sin tocar contratos) y la consulta antes de refinar drafts.
